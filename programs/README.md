# Programs

Under the [Technology Governance Policy](../governance-policy.md), COPA approves and pays for software work one program at a time. A **program** is a defined piece of work with a scope, a cost cap and a clear finish line. It is not a piece of software; one program may touch several systems.

## How a program works

1. **Proposed.** A one-file proposal is added here using the [template](TEMPLATE.md) and posted to the board for comment.
2. **Approved.** The board votes on the scope and the not-to-exceed cost. The vote date and budget are recorded at the top of the file. A director who would be paid for the work does not vote.
3. **In progress.** Progress, hours (billed and donated) and spend against the cap are added to the file's Updates section at least monthly. Anything that would exceed the cap goes back to the board first.
4. **Done.** When the "done when" list is met, the final hours and cost are recorded and the program is closed. A program can also be stopped by the board at any point.

Who builds a program is named in the proposal. If that person is paid, their rate and terms live in a separate written engagement, not in the program file.
